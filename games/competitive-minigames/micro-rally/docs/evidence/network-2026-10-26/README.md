# Micro Rally: свидетельства сетевого блока

26 октября 2026. Подготовка в отдельной ветке `codex/micro-rally`; публикация
Crates и доставка на устройства не выполнялись. Портативки не опрашивались.

## Полный заезд через настоящий SDK

`sdk-2-full-race-before-close-fix.log`, снимок `5bfdb9da8dcf9ae8`
(`full-race-build-manifest.json`): два отдельных процесса Godot, 14 ботов,
четыре круга, обычные физика/оружие/предметы/возврат. У обоих игровых участников
прогресс достиг 1280, таблицы результатов совпали, оба начали второй заезд.
Затем смена профиля одного участника завершила матч у обоих; состав лобби
сохранился. Весь сценарий занял 216,9 секунды, это не время отдельного гонщика.

В журнале обнаружен дополнительный дефект: запоздалое подтверждение закрытого
канала вызывало `channel_unavailable` и обрыв общего SDK-подключения у второго
участника. Сам заезд/реванш прошёл, но сохранение SDK после выхода этим старым
прогоном не доказано. Исправление отдельно проверяется ниже; старый журнал
сохранён без удаления предупреждения.

## Исправленный вариант и 16 процессов

Финальный снимок **`7f907609f891e447`**, `build-manifest.json`.
При завершении матча отменяется ожидание ответов закрытых сетевых запросов,
запоздалые записи старого канала игнорируются. Действующие avatar-запросы и
аутентифицированное SDK-подключение сохраняются; отзыв самого профиля по-прежнему
закрывает его. В проверку добавлено ожидание запоздалых ответов и требование
сохранить регистрацию у всех участников, кроме действительно отозванного.

**`sdk-16.log`: 3 passed, 0 failed, 56,9 секунды.** Подтверждены одинаковые
результаты, все 16 разных мест, общий реванш, завершение у всех после отзыва
одного профиля, сохранение состава лобби и SDK-регистрации у остальных 15.
Повторного `channel_unavailable`/обрыва SDK и ошибок GDScript не обнаружено.

`network_test.gd.log`: 0 ошибок. Проверены барьер всех Ready, своё место и
управление, таймаут ввода, запрет подмены состояния клиентом, последний слот,
фары, прогресс реплики, меню без общей паузы, неверные числа, старые команды
прошлого заезда, ограничение очереди и запоздалые ответы закрытого канала.

Нативный 16-процессный сценарий использует реальные PlatformHost, SdkNetwork,
LobbyCoordinator/LobbyRuntime, Godot и TLS helpers. Подменена только передача
сигнальных сообщений провайдера между экземплярами лобби. После предварительного
запуска сцен выполняется обычный Ready/Start, 15 секунд физического движения,
проверка общего результата, реванша и отзыва профиля. **Финиш в этом сценарии
задан тестом**; это не полный четырёхкруговой заезд 16 сетевых игроков.
Контейнер ограничен 4 CPU / 6 GiB, внешний network отключён, каналы работают
через loopback. Это не измерение производительности 16 портативок.

По сравнению с полным двухпроцессным заездом изменены только обработка завершения
SDK-канала, привязка эмоций/звука подбора к своему участнику, проверки и документы.
Физика, дистанция, формат ввода/состояния и условия заезда сохранены; различия
манифестов сверены. Полный заезд повторно ради неизменённой физики не запускался.

## Регрессии, экспорт и кадр

- `journey_test.gd.log`, `weather_test.gd.log`: 0 ошибок на `5bfdb9da8dcf9ae8`.
  Сохранены одиночная пауза/управление/реванш, оружие, дождь и сцепление.
- Экспорты Windows x86_64 / Linux ARM64 / Linux x86_64 прошли на финальном
  `7f907609f891e447`; журналы `export-*`. Исходные хеши совпали с рабочими файлами.
- `preview.png` и `preview.log`: реальный кадр Windows Vulkan Mobile,
  1280×720, 16 машин, `5bfdb9da8dcf9ae8`. Это одиночный автоматический прогон
  для проверки сохранения рендера и мягкого размытия всех краёв. HUD резкий.
  Короткий захват сообщил 60 FPS; устойчивый замер и сетевой рендер не заявлены.
- При выходе headless-процессов остаётся предупреждение о двух ObjectDB
  instances. Устранение этой утечки в данном блоке не заявляется.

Интернет/Fluxer, реальные контроллеры, холодный запуск 16 устройств, задержка
управления, принятие графики владельцем, полный кубок/награды и подписанный
пакет остаются открытыми. [Контракт и следующий порядок](../../NETWORK.md).
