# Аватар: граница между Pocket Golf и TrainerOS

Владелец выбрал отдельные самостоятельные игры с единым аватаром пользователя.
Гардероб, переодевание, внешность, владение предметами и сохранённый комплект
принадлежат TrainerOS/SDK. Godot — движок этой игры, а не обязательный формат SDK.

## Подготовлено сейчас

`scripts/avatar_anchor.gd` — точка установки визуального представления. Метод
`install_visual(node, player_id)` принимает уже подготовленный `Node3D`; повторная
установка снимает прежнее представление. `clear_identity()` освобождает его.
`play_action(action)` передаёт семантическое действие presenter-объекту, если тот
поддерживает этот метод. Это локальная граница игры, **не утверждённый API аватара SDK**.

Игра задаёт положение рядом с активным мячом, направление удара и действия
`golf_putt` / `celebrate`. Её расчёт удара не зависит от костюма, скелета, длины
анимации или геометрии модели. Визуальный персонаж не участвует в столкновениях.
Разрыв SDK-соединения освобождает представление прежней личности. Для автономной
игры остаётся простой временный маркер без выдуманной SDK-идентичности.

`addons/traineros/client.gd` реализует только существующие Platform API v1 / Lobby /
records. В нём нет выдуманного `avatar.get`, локального гардероба или параллельной
системы профилей. В существующем сетевом контракте self/peer — участники сессии;
их связывание с публичным описанием аватара должен определить SDK.

## Когда модуль будет готов

1. Согласовать контракт получения образа: идентичность локального и удалённого
   игрока, ревизия внешности, разрешённые ресурсы, обновление и отзыв данных.
2. Подключить официальный Godot-presenter SDK к `AvatarAnchor`, сохранив
   нейтральное описание внешности/одежды независимым от движка.
3. Согласовать метры, направление вперёд, точку пола, точки крепления клюшки,
   rig/анимации удара, ожидания и реакции. Наличие GLB само по себе не закрывает
   семантику костюмов, corrective morphs и анимационных событий.
4. Проверить несколько комплектов одежды, пересечения, одинаковый образ у обоих
   участников и замену внешности. Обновления во время удара применять на безопасной
   границе анимации. Игра не должна переписывать постоянный образ пользователя.
5. Проверить производительность и читаемость на Odin/Flip, а также возврат после
   смены профиля/разрыва соединения. До этого не объявлять аватар интегрированным.

Общий SDK-плагин пока подготовлен внутри проекта игры для проверки контракта.
После согласования его следует вынести в SDK и версионировать как зависимость;
дублировать его вручную во всех будущих играх не предполагается.
